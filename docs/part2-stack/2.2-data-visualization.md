## 选型：三套方案各管一段

物联网前端的图表需求大致三类：实时遥测曲线、轻量仪表盘、设备拓扑关系图。没有全能选手，先对比再选型：

| 对比维度 | ECharts（demo 采用） | Chart.js | AntV G6 |
| --- | --- | --- | --- |
| 实时高频更新 | 强：setOption 增量更新，大数据集有渐进渲染优化 | 中：每次 update 全量重算，需自己控频 | 弱于时序场景，定位是关系图 |
| 包体积 | 大：全量引入约 1MB 量级（demo 构建已见超限警告），可按需裁剪 | 小：轻量场景首选 | 中大：含图分析与布局引擎 |
| 时间轴能力 | 内置 time 轴，markLine / markArea / dataZoom 等标注缩放齐全 | time 比例尺需额外安装日期适配器 | 非其目标场景 |
| 关系图能力 | 有基础 graph 系列，复杂图分析吃力 | 基本没有 | 核心强项：拓扑、力导、层级布局 |
| 学习成本 | 中：option 配置项繁多 | 低：直觉式 API | 中高：图分析领域概念多 |
| 生态与社区 | 大：示例丰富、中文资料多 | 大：轻量场景事实标准 | 中：图可视化领域主流 |

demo 的结论：**通用实时遥测曲线选 ECharts**（图表能力与时间轴标注最齐）；如果只做几个仪表盘/迷你图且对体积敏感，Chart.js 足够；设备拓扑、组网关系、链路图交给 G6。三者不互斥，真实监控台常常是 ECharts 画曲线 + G6 画拓扑。

## useECharts：把图表生命周期绑进组件

demo 没有在组件里裸调 `echarts.init`，而是收敛成一个组合式函数，注释里点明了它要防的两个经典坑：卸载不 dispose 导致实例泄漏、容器尺寸变化不 resize 导致曲线压扁错位。

```ts
// 文件: demo/src/composables/useECharts.ts
export function useECharts(hostRef: Ref<HTMLElement | null>) {
  let chart: echarts.ECharts | null = null
  let ro: ResizeObserver | null = null
  const ready = ref(false)

  /** 惰性初始化：宿主元素渲染完成前返回 null，调用方需判空 */
  function ensure(): echarts.ECharts | null {
    if (chart || !hostRef.value) return chart
    chart = echarts.init(hostRef.value)
    ro = new ResizeObserver(() => chart?.resize())
    ro.observe(hostRef.value)
    ready.value = true
    return chart
  }

  function setOption(
    option: echarts.EChartsCoreOption,
    opts?: { notMerge?: boolean; lazyUpdate?: boolean },
  ): void {
    const c = ensure()
    c?.setOption(option, { lazyUpdate: true, ...opts })
  }

  onBeforeUnmount(() => {
    ro?.disconnect()
    ro = null
    chart?.dispose()
    chart = null
    ready.value = false
  })

  return { ensure, setOption, ready }
}
```

逐段拆解三个关键设计：

1. **惰性初始化 `ensure()`**：不在 setup 时立刻 init，而是首次 setOption 时才执行 `echarts.init(hostRef.value)`。宿主元素若还没渲染（`v-if` 未通过、尺寸还是 0），ensure 返回 null，调用方判空跳过——避免了"在 0×0 容器上 init 出一张看不见的图"。
2. **ResizeObserver 自动 resize**：监听的是**宿主元素**而不是 window。窗口拖动、侧栏折叠、flex 布局重排，只要容器尺寸变了就调 `chart.resize()`，比 `window.onresize` 精准得多——页面没变但容器变了的情况（比如抽屉推开）它也能捕获。
3. **`onBeforeUnmount` 里 dispose**：`ro.disconnect()` 停止观察 + `chart.dispose()` 销毁实例（连同 canvas 事件监听）。实例和观察器都与组件生命周期严格绑定，组件卸载即释放，切换路由多少次都不会泄漏。

另外 `setOption` 包装默认带了 `lazyUpdate: true`，让 ECharts 把更新合并到下一帧执行，高频更新时能天然去抖。

## TelemetryChart：实时曲线的实现策略

组件从 store 拿数据、每 800ms 批量刷新一次，是 demo 可视化层最核心的一个组件。先看序列定义——曲线组随产品类型自动切换：

```ts
// 文件: demo/src/components/TelemetryChart.vue（节选）
const seriesDef = computed<SeriesDef[]>(() =>
  entry.value?.profile?.productId === 'pl01'
    ? [
        { key: 'power', name: '功率 (W)', color: '#f59e0b' },
        { key: 'voltage', name: '电压 (V)', color: '#38bdf8' },
      ]
    : [
        { key: 'temp', name: '温度 (℃)', color: '#fb7185' },
        { key: 'humi', name: '湿度 (%RH)', color: '#38bdf8' },
      ],
)
```

渲染函数里有五个值得圈点的细节：

```ts
// 文件: demo/src/components/TelemetryChart.vue（节选）
function render(): void {
  const e = entry.value
  if (!ensure()) return
  const win = e?.window ?? []
  const series = seriesDef.value.map((s) => ({
    name: s.name,
    type: 'line',
    showSymbol: false,
    smooth: true,
    // 数据对 [时间戳, 值] 配合 time 轴：按真实时间定位，缺失字段用 null 断开
    data: win.map((p) => [p.ts, p[s.key] ?? null]),
    lineStyle: { color: s.color, width: 1.5 },
    itemStyle: { color: s.color },
    // 只有温度序列画阈值线；阈值来自设备侧 setThreshold 指令的最新值
    ...(s.key === 'temp' && e
      ? {
          markLine: {
            silent: true,
            symbol: 'none',
            lineStyle: { color: '#f43f5e', type: 'dashed' },
            data: [{ yAxis: e.tempThreshold, label: { formatter: `阈值 ${e.tempThreshold}℃`, color: '#f43f5e' } }],
          },
        }
      : {}),
  }))

  setOption(
    {
      xAxis: { type: 'time', axisLabel: { formatter: (v: number) => fmtClock(v) } },
      yAxis: { type: 'value', scale: true },
      series,
      // …… legend / tooltip / grid 等样式配置从略
    },
    { notMerge: true },
  )
}
```

- **`type: 'time'` 轴 + `[ts, value]` 数据对**：x 轴用时间轴，数据点带真实时间戳，ECharts 按时间定位。这是处理"稀疏上报"（第 2.4 章的低功耗批量数据）的前提——点与点的间距忠实反映真实间隔。`scale: true` 让 y 轴不强制从 0 开始，温度 18~34℃ 的波动才看得清。
- **滑动窗口取数**：`e.window` 是 store 里的遥测滑窗（上限 120 点，见第 2.3 章），图表不持有任何数据副本，store 是唯一数据源。
- **`p[s.key] ?? null`**：插座没有温度字段、传感器没有功率字段，缺失指标画 null，序列自然断开，不会把 undefined 画成 0。
- **markLine 阈值线**：只在温度序列上画，阈值 `e.tempThreshold` 来自设备侧 `setThreshold` 指令的最新值——前端画的线和设备判告警的线是同一条。
- **`notMerge: true`**：全量替换 option。没有它，从传感器详情切到插座详情时，上一台设备的温湿度序列会残留在图里跟功率曲线叠加（见实操任务 2）。

最后是更新节奏——这是整个方案的性能关键：

```ts
// 文件: demo/src/components/TelemetryChart.vue（节选）
let timer: ReturnType<typeof setInterval> | null = null
onMounted(() => {
  render()
  timer = setInterval(render, 800) // 800ms 批量刷新：解耦「消息频率」与「图表帧率」
})
onUnmounted(() => {
  if (timer) clearInterval(timer)
})
```

8 台设备混合上报时，消息可能每秒十几条。若每条消息触发一次 setOption，渲染频率就被消息频率绑架，主线程长期高占用。demo 的做法：**消息只写 store（很快），图表每 800ms 从 store 拍一次快照**——人眼对 0.8 秒的延迟无感，CPU 占用却降了一个量级。"消息频率"与"图表帧率"就此解耦。

## 包体积与替代方案：按需引入、Chart.js、G6

### ECharts 按需引入（tree-shaking）

demo 为了教学清晰用了全量引入（useECharts.ts 里 `import * as echarts from 'echarts'`），代价是 `pnpm build` 时 Vite 会打印 chunk 体积超限警告——全量 ECharts 让主包达到 1MB 量级。生产项目应改用按需引入，只注册用到的图表与组件：

```ts
// 文件: 文档示例（按需引入写法，未进入 demo 源码）
import * as echarts from 'echarts/core'
import { LineChart } from 'echarts/charts'
import {
  GridComponent,
  LegendComponent,
  MarkLineComponent,
  TooltipComponent,
} from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'

echarts.use([LineChart, GridComponent, LegendComponent, MarkLineComponent, TooltipComponent, CanvasRenderer])
// 之后把 useECharts.ts 里的 `import * as echarts from 'echarts'` 换成 'echarts/core'，
// init / setOption / dispose 的 API 完全不变。
// 注意：漏注册的组件不生效——没注册 MarkLineComponent，阈值线就画不出来。
```

demo 实际用到了 LineChart、grid、tooltip、legend、markLine 五类能力，按需引入后主包能砍掉大半。

### Chart.js 等价实现思路

同样的实时曲线用 Chart.js 4 写，核心差异是：time 比例尺要装日期适配器，高频追加数据时建议关动画、跳过解析：

```ts
// 文件: 文档示例（Chart.js 等价思路，未进入 demo 源码）
import { Chart, registerables } from 'chart.js'
import 'chartjs-adapter-date-fns' // time 比例尺需要日期适配器

Chart.register(...registerables)

const chart = new Chart(canvas, {
  type: 'line',
  data: { datasets: [{ label: '温度 (℃)', data: [{ x: Date.now(), y: 25.3 }] }] },
  options: {
    parsing: false,   // 数据已是 {x, y} 结构时跳过解析，降低 CPU
    animation: false, // 高频实时曲线建议关动画
    scales: { x: { type: 'time' } },
  },
})

// 追加数据后以 'none' 模式更新：跳过动画全量重绘
chart.data.datasets[0].data.push({ x: Date.now(), y: 26.1 })
chart.update('none')
```

### G6 拓扑图思路

设备组网拓扑（网关 → 各设备）是 G6 的主场：节点状态映射颜色，上下线只需更新数据重绘：

```ts
// 文件: 文档示例（G6 拓扑图思路，未进入 demo 源码）
import { Graph } from '@antv/g6'

const graph = new Graph({
  container: document.getElementById('topo')!,
  data: {
    nodes: [
      { id: 'gw', data: { name: '网关', online: true } },
      { id: 'gh01-001', data: { name: '育苗棚 A1', online: true } },
      { id: 'gh01-004', data: { name: '育苗棚 C1', online: false } },
    ],
    edges: [
      { source: 'gw', target: 'gh01-001' },
      { source: 'gw', target: 'gh01-004' },
    ],
  },
  node: {
    style: {
      size: 40,
      // style 属性支持函数，入参为节点数据：在线状态映射到节点颜色
      fill: (d) => (d.data.online ? '#22c55e' : '#64748b'),
      labelText: (d) => d.data.name,
    },
  },
  behaviors: ['zoom-canvas', 'drag-canvas'],
})
graph.render()

// 设备上下线时：更新 nodes 数据后调用 graph.setData(newData) 重绘即可
```

以上两个片段是文档级示例，没有进入 demo 源码；需要时按思路补全即可。

## 最佳实践与常见坑

**坑 1：组件卸载不 dispose，内存泄漏**
- 现象：详情页来回切换十几轮后，页面渐卡；DevTools Memory 堆快照里 ECharts 实例（带 `$id` 的对象）越积越多。
- 原因：每次 mounted 都 init 一个新实例，卸载时没 dispose——实例、canvas 事件监听、ResizeObserver 全部泄漏。
- 解法：图表逻辑收敛进 useECharts 这类封装，`onBeforeUnmount` 里 `ro.disconnect()` + `chart.dispose()`；组件里不要散落裸调 `echarts.init`。

**坑 2：逐消息 setOption，高频上报时卡顿**
- 现象：设备多、上报频繁时主线程长期高占用，页面掉帧、输入卡顿。
- 原因：每条 MQTT 消息都触发一次 setOption 重绘，渲染频率被消息频率绑架。
- 解法：定时批量快照——消息只写 store，图表每 800ms 取一次数（TelemetryChart 的 `setInterval(render, 800)`），把"消息频率"与"图表帧率"解耦。

**坑 3：time 轴误用 category，稀疏数据空隙被挤压**
- 现象：低功耗设备（15 秒一批、批内间隔 30 秒）的曲线点被均匀铺开，"稀疏感"消失，时间刻度与真实时间对不上。
- 原因：category 轴按数据**下标**等距排布，完全不感知真实时间戳；点少时每个点被拉到一样宽。
- 解法：`xAxis.type: 'time'` + 数据对 `[ts, value]`（TelemetryChart 的写法），让横轴按真实时间定位。

**坑 4：在 0×0 容器上 init，图表空白**
- 现象：图表区域空白，console 无报错；或首次渲染正常、从隐藏状态切回后尺寸不对。
- 原因：宿主元素还在 `v-if` 隐藏或布局未完成时 init，量到的高度是 0。
- 解法：惰性 `ensure()` 保证挂载后才 init；ResizeObserver 兜底尺寸变化；给宿主元素显式高度（demo 的 `.chart-host { height: 320px }`）。
